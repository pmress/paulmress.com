Lab · Experiment 001

Can AI replace a CMS?

This domain used to run on a GoDaddy website builder. Now it runs on a written brief, an AI pair-programmer, and a design system instead of an admin panel — and this site is the experiment. Not a case study written after the fact: the log, as it actually happened.

Ongoing Claude · GitHub Pages · GitHub Actions · Google Drive · Playwright

The Hypothesis

I think an AI pair-programmer can fully replace a traditional CMS for a personal site — with real version control and design consistency a CMS doesn’t give you by default, and without a monthly SaaS fee — as long as I’m willing to type instructions instead of clicking through an admin panel.

The Thing Built

You’re already inside it

There’s no separate demo for this one. Every page on paulmress.com — this one included — was written, styled, and shipped the same way. Five steps, every time, whether it’s a typo fix or a brand-new page.

Write the brief

Plain language, in Google Docs or straight in chat — what should change, and why.

Hand it to AI

The brief becomes a prompt. Claude writes the real HTML, CSS, and copy — not a mockup.

The design system governs it

Every new component has to match what’s already documented on Design System — nothing gets invented from scratch.

Committed to GitHub

A real commit, a real message — permanent and reviewable. Nothing silently overwritten.

Live in about a minute

GitHub Pages rebuilds and deploys automatically. No IT ticket, no agency, no waiting.

What follows is the part a pipeline diagram can’t show: the actual receipts, and what I got wrong along the way.

The Receipts

Two real exchanges, unedited

Not summaries of what happened — what was actually asked, and what actually came back.

Receipt 01 · A nav bug, found and fixed in one pass

→ Input

“The design system page doesn’t have the nav menu that everything else does. We need to fix that.”

← AI output

Diagnosed the cause — that one page had its own bespoke header instead of the shared site nav — rebuilt it with the real hamburger menu and slide-in panel, and caught a second, unrelated bug in the process: a footer script would have thrown a silent error on that page the moment the shared script was added. Fixed both, screenshot-tested at desktop and mobile, deployed.

✓ Outcome

Live in one pass. No revision needed — the fix matched every other page exactly, because the design system left no room to invent a different pattern.

Receipt 02 · The decision the AI got wrong

← AI output (earlier)

A full technical plan for an “Ask Dr. Paul” chat feature — researched, priced, and built around OpenAI’s models, because that was the provider the source material referenced.

→ Input

“I don’t want to use GPT. I want to use you.”

✓ Outcome

The entire plan got rebuilt around Claude instead — and the bigger question surfaced along with it: not which AI provider to use, but whether a talking avatar of himself was something Paul wanted to exist at all. Still open. See “next experiment” below.

What Worked, What Didn’t

Observations, not conclusions

Worked well

Turning a written brief into a shipped page, same sitting — no back-and-forth once the brief was clear.

Visual consistency enforced automatically — new components have to justify themselves against the design system instead of getting invented fresh.

Catching problems before they ship — the footer-script bug in Receipt 01 never made it live.

Needed a human

Whose voice a feature gets to use — an identity call, not a technical one.

Knowing when a feature is honest and useful versus just impressive — still unresolved for the AI avatar idea.

Aesthetic taste on anything visual — that’s a feel call, not a logic call.

The Human Advantage

What still required me

Receipt 02, side by side.

What the plan looked like

A phased rollout

Text chatbot first, then a talking avatar — researched and priced against OpenAI’s models, because that was the provider already in the source material.

What I actually decided

Wrong provider. Wrong question.

Not OpenAI — Claude. And the phased rollout didn’t matter yet, because the real question hadn’t been asked: should an avatar of me exist at all, or does that cross into pretending to be me?

What Changed My Mind

I expected the hard part to be teaching the AI my writing voice and visual taste. It picked those up fast. The hard part turned out to be everything upstream of taste — deciding what’s true enough to say about myself, when a feature is honest instead of just clever, and when “good enough to ship” is actually the wrong bar.
