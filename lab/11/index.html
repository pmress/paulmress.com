Lab · 11

Can AI deploy more efficiently through the browser than through a local command line?

Earlier this project tested whether Claude could get real write access to this site’s GitHub repo without ever holding credentials of its own. The answer was: only by asking Dr. Paul to run a command-line tool on his own machine, step by step, with Claude unable to type into his terminal directly. This experiment asks the practical follow-up — is that actually the more efficient path, or is Claude driving the browser itself, from inside Cowork, faster and cheaper?

Ongoing Updated Sept. 16, 2026

Hypothesis

AI can more efficiently deploy code to GitHub via Cowork using the browser.

This compares two real, tested paths from this project’s own history — it isn’t a controlled study across other repos, other tasks, or other AI tools.

Method

Local command line
Dr. Paul installs Git and Claude Code CLI→Fix PATH, shell type, and folder-permission errors→Claude guides every step by chat, since it can’t type into his terminal→One test commit lands, then gets cleaned up
Browser, from Cowork
Claude opens GitHub’s own upload page directly→Uploads the file and writes the commit message itself→Commits, with Dr. Paul’s yes in chat→Verifies the live page itself, no local machine involved

Build

This page, and the project notes documenting the earlier command-line test, were written entirely inside this Cowork session.

→

Upload

Claude drove GitHub’s own web-upload page directly — the same path this project has used since the beginning, with no local software involved at all.

→

Measure

Claude pulled its own real usage numbers from this session’s own record, instead of estimating them, and timed the deploy from a wall clock.

→

Verify

The commit, the live page, and the Actions build were all checked directly in the browser before this write-up was called done.

Tech

Claude Cowork Claude in Chrome GitHub web-upload UI

The experiment

The receipts for this one are this very deployment — not a separate test run.

AI handled

  • Writing up the earlier command-line investigation and this comparison, entirely inside Cowork
  • Building and deploying this page through the browser, with no local machine involved
  • Pulling its own real time and token numbers from this session’s own record, instead of guessing

Dr. Paul handled

  • Setting the hypothesis: that the browser path is the more efficient one
  • Confirming the deploy
  • Reviewing the receipts and giving the finding below

0 local software installed · 0 turns spent fixing PATH, shell-type, or permission errors · 1 person’s single “yes” needed to commit

Worked: Writing, building, and deploying this page happened start to finish without Dr. Paul’s own computer ever being touched — no install, no PATH fix, no walking him through a terminal.

Constraint: This is one deploy compared against one earlier session, not a controlled trial — and the browser path only works because this project already committed to the GitHub web-upload flow years before Claude Code CLI was ever tested.
